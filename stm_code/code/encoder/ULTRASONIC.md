# HC-SR04 obstacle hold

PB8 is the push-pull TRIG output; PB9 is ECHO on both-edge EXTI9_5 (priority 0). Verify the sensor's 5 V supply, common ground, and suitable ECHO level conversion to the MCU input before connecting. Existing timers retain their PWM/encoder settings. TIM2's existing 50 us update IRQ issues a 50 us trigger every 60 ms and a 30 ms echo timeout. DWT measures echo edge separation without resetting the PID cycle counter. There is no blocking delay or additional timer.

The decision distance is a nominal 10 cm at 343 m/s (reduced from 25 cm on 2026-10-05 at the user's request; this is below the earlier 20 cm protection requirement and carries no temperature/sensor margin): a valid echo width <=584 us (`ULTRASONIC_NEAR_ECHO_US`) is a near sample; a wider valid echo is a far sample. Each completed trigger attempt fills one slot in a rolling 20-attempt window. Only after all 20 slots are filled do 16 or more near samples assert the obstacle hold, or 16 or more far samples release it. The remaining four slots may contain the opposite result or invalid measurements. A `NO_ECHO` timeout fills a slot but counts as neither near nor far; an unplugged or failed sensor therefore cannot by itself release the startup or obstacle hold. Falling edges without a matching rise are ignored. Short pulses are treated conservatively as near. Each sample updates the existing window instead of resetting consecutive counts. This is a filtering rule, not a sensor-health diagnostic or a substitute for physical stopping protection. Very close objects, angled surfaces and acoustic interference require physical testing. The margin is an engineering allowance, not a guarantee for every temperature, target or sensor failure; validate the actual 10 cm boundary and the resulting stopping distance across the intended operating conditions.

Startup inhibits outputs until a full window contains at least 16 valid far samples; this unknown-range inhibit does not publish obstacle events or request red. An asserted obstacle requests the existing red 500 ms ON/OFF effect. `OBSTACLE_HOLD\r\n` and `OBSTACLE_CLEAR\r\n` are emitted once per actual obstacle transition from main context, never from an ISR. Startup clear produces neither event. The ROS bridge separately exposes these events for future TTS; firmware does not perform speech.

The mission state, section count and pending capture ACK are retained during hold. TIM3 section IRQ processing is inhibited and the saved TIM3/TIM4 counts are restored on release; movement/coasting during hold is deliberately excluded from planned section progress. Mission transition delays use a pauseable operational clock, as do actuator and debug timers. PID is stopped and restarts with fresh encoder/time samples; its real-time watchdog and DWT source are unchanged. Existing faults remain latched and take precedence over clearance. An IDLE/STOP/fault during hold cancels automatic drive restoration. A section selected immediately before an echo interruption is deferred and started on clearance.

Only normal mission drive resumes automatically. DEBUG_TEST and ACTUATOR_TEST drive does not restart. All cleaning outputs are stopped, their pending energizing commands are discarded, and a fresh post-clear control command is required. UART barriers discard stale ON/DBG frames while retaining START/capture ACK so initial start and capture completion can continue after clearance. Explicit OFF and test-stop commands remain accepted. The existing fatal `Robot_EmergencyStop()` remains a permanent fault API; ultrasonic hold does not call it.

CubeMX `.ioc` records PB8 output, PB9 rising/falling EXTI and its NVIC entry. Keep USER CODE integration in TIM2 IRQ and the HAL GPIO callback. Review regenerated code, particularly RGB active-low initial pin levels, and rebuild. Main-loop UART event delivery and RGB mode changes can lag the ISR's output stop. At the 60 ms trigger interval, filling 20 attempts takes about 1.2 s; a newly appearing obstacle can remain unconfirmed for many attempts. The stopping distance depends on speed, braking/coasting, the window delay and interrupt latency; the code does not establish a physical safe stopping distance. Measure stop latency and distance on the bench before permitting motion near hazards.

Host tests must cover 584/585 us boundaries, retention of 467 us (8 cm) as near and 1458 us (old 25 cm) as far, the full-window 16-of-20 threshold in both directions, invalid/no-echo slots, rolling eviction, startup hold, DWT wrap, ISR-side stop, all mission states, transition-time freeze, capture ACK retention, fault/IDLE precedence, fresh-command-only cleaning restart, and PID-enabled/disabled interlocks. Static GPIO checks and ARM builds cover interrupt wiring. Board validation remains: trigger/echo waveforms and level shifting, measured boundary targets, obstruction during each mode, motor/cleaner stop latency, resumed distance, RX traffic/PID/RGB timing and event delivery. No firmware flashing or Jetson deployment is performed by this change.
